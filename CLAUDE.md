# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A browser-only app (no build step, no framework, no backend) for writing work setup
procedures per product (grouped by product line) and per machine, and exporting them
as a black-and-white/colour PDF. Data lives only in the user's browser. Work is done on
the `claude` branch.

## Commands

- Run: open `index.html` directly, or `npm start` (serves on http://localhost:8000).
- Tests (Node 18+, no dependencies): `npm test` (= `node --test tests/*.test.js`).
- Single test file: `node --test tests/zip.test.js`
- Single test by name: `node --test --test-name-pattern="addItem" tests/utils.test.js`
- Formatting: code is formatted with Prettier 3.3.3 (`npx -y prettier@3.3.3 --write js/*.js css/styles.css index.html`). There is no linter config.
- Browser tests: `npm run test:e2e` (`tests/e2e/app.test.js`, node:test + the `playwright` library, not `@playwright/test`). Needs `playwright` resolvable (CI: `npm install --no-save playwright@1.63.0 && npx playwright install --with-deps chromium`). They block all internet requests, so they also check that the app works offline, and they search the downloaded PDF bytes for text (jsPDF output is uncompressed).
- CI: `.github/workflows/test.yml` runs both on every push and pull request.

## Architecture

Classic `<script>` files (not ES modules) share globals, including top-level `let`/`const`; load order in `index.html` matters:
`vendor/jspdf` → `utils.js` → `storage.js` → `zip.js` → `state.js` → `ppe.js` → `views.js` → `undo.js` → `transfer.js` → `pdf.js` → `log.js` → `markup.js` → `approval.js` → `activity.js` → `events.js` → `access.js` → `admins.js` → `approvers.js` → `lock.js` → `app.js` (start-up). Code that runs at load time may only use globals from earlier files; functions may use any. A new script must also be added to `FILES` in `sw.js` (and bump `VERSION`).
`utils.js` and `zip.js` end with `if (typeof module !== "undefined") module.exports = …` so the Node tests can `require` them. Keep that guard, and keep `utils.js` free of DOM access.

### State and rendering (`state.js`, `views.js`, `events.js`)
- One mutable global `S` holds all data: `{ co: {name, depts:[{id,name}], done}, logo, lines:[{id,name,products:[item]}], machines:[item], lastBackup, log:[{t,kind,name,code,rev,line,dept,ref,who,person,file,pages,status}], act:[{t,type,text,who,code,role}] }`. Products and machines share one item shape: `{id, name, code, rev, date, dept, prod:[img], pack:[img], tools:[{n,s,q}], ppe:[key], ppeo, steps:[{h, t, img, more, warn, wtype, subs:[{t, img, more, warn, wtype}]}], th, tm, tech, by, appr, ap}` (`ap` = approval, see below). Images are JPEG/PNG data URLs. Step and sub-step photos (at most `MAX_STEP_PHOTOS` = 3, enforced in the upload handler and by hiding the add button): the first in `img`, any further ones in `more` (left out when there are none, so older data and approval fingerprints are unchanged); always read and write them through `photosOf(o)` / `setPhotos(o, arr)` in `utils.js`, and the PDF lays them out with `picRows`. Missing optional fields mean "not set" (e.g. `warn === undefined` = no note box; no `wtype` = "warning"; no `dept` = first department via `deptOf`).
- Navigation globals: `T` = screen (`"co"` company setup, `"h"` home, `"p"` products, `"m"` machines, `"x"` export & import, `"log"` Logs page (tabs `LTAB`: activity, print log, code usage), `"ap"` approvals), `V = {l, p}` = selected line/product, `MID` = selected machine. `P()` returns the item being edited (product or machine).
- `R(keep)` re-renders the whole screen by building an HTML string into `#app`. `keep = true` keeps the scroll position and restores focus/caret via `data-*` attribute selectors. Views: `CoV`, `HomeV`, `MV`, the product/machine page inside `R`, `XV` (export & import); helpers such as `stepHtml`, `noteHtml`, `toolsHtml`, `tree`.
- Events use document-level delegation: `click` dispatches on `data-a="<action>"` (with `data-i`/`data-j` indexes) in one large if/else chain, then calls `save()` and `R()`. Typing goes through the `input` listener, which writes into `S` by data attribute (`data-f` field, `data-h`/`data-s` step, `data-ss` sub-step, `data-w` note, `data-tool`). It saves but does not re-render. File inputs, selects and tick boxes go through the `change` listener.
- Any user-visible text built into HTML must go through `esc()`.

### Persistence (`js/storage.js`, global `Store`)
- IndexedDB database `setup-procedures`, store `kv`: key `"state"` holds `S` with every image replaced by an `"img:<id>"` reference, and each image is its own record. Image-bearing fields are walked by `mapImgs` in `utils.js`; when adding a new image field, update `mapImgs`, `imgPlanner.item`, `imgRefs` and `imgBytes` together.
- Falls back to localStorage key `sp` (about 5 MB) when IndexedDB is unavailable; data found under `sp` is migrated to IndexedDB on load.
- `save()` writes immediately (one write in flight plus one queued); `writeNow()` resolves `false` when storage is full, and callers use it to roll back photo and logo additions.
- Per-browser UI preferences (Group by, collapsed tree groups, help panels open, watermark, PDF photo size) live in localStorage `sp-view`, separate from the data. Every access is wrapped in try/catch.

### Backups and sharing (`js/zip.js` + `utils.js`)
- `Zip.make` writes stored (uncompressed) entries with UTF-8 names. `Zip.read` also inflates deflated entries via `DecompressionStream`, so ZIPs re-saved by Windows/macOS still import.
- Export ZIP layout: `data.json` (images replaced by relative paths such as `photos/<line>/<product>/step-2-1.jpg`), the image files, `logo.png`, and `READ ME.txt`. Planned by `planBackup(S)` (full backup) or `planItems(list, company)` (selection; format `"setup-procedures-items"`). The older single-item format `"setup-procedures-item"` and plain-JSON backups must keep importing.
- Import: `readFile` → `fileContents` (packs, company, full backup) → preview on the `"x"` screen → `applyImport`, which either replaces `S` or merges via `addItem` (line and department matched by name). `imgRefs`/`similarPath` build the missing-photo report.

### PDF (`mkPdf` in `pdf.js`)
- jsPDF A4 in mm, drawn top to bottom with a running `y` and `need(h)` for page breaks. `stepH`/`subH` precompute heights so a step (with its notes, photos and sub-steps) stays on one page when it fits, and the "Procedure" heading stays with step 1.
- Order: header (company · department · "Setup procedure", logo top right), meta row, Safety equipment signs, product and packaging photos, Tools required table, Machine settings table (`p.set = [{n, v, u}]`, rows with a name via `settingsOf`; in `apContent` and `itemDiff` only when non-empty), Procedure, Approval (time/technicians table, then signatures), footer and optional watermark on every page.
- Note colours are defined twice and must stay in sync: `NOTE_PDF` in `mkPdf` and the `--dg`/`--cau`/`--nt` CSS variables. Photo print sizes come from `PHOTO_SIZES`.
- The built-in Helvetica font has no symbol glyphs; the warning triangle and info circle are drawn with shapes.
- PPE signs (`ppe.js`) are SVG strings: inline on the page, converted to PNG through a canvas (`ppePng`, cached) for the PDF.

### Log in and roles (`lock.js`)
- Three code lists: `ACCESS_CODES` (`js/access.js`, role `author`), `ADMIN_CODES` (`js/admins.js`, role `admin`), both `[[name, codeHash(code)]]` written by `scripts/access-code.js` (`npm run code` / `npm run admin`), and `APPROVERS` (role `approver`, matched through `apKeys(code).pub`). Plain codes are never committed. `codeHash` = SHA-256 (pure JS `sha256` in `utils.js`, since `crypto.subtle` may be missing on `file://`) of a fixed prefix + `normCode` (upper case, no spaces/dashes).
- `app.js` calls `startApp()` only if `hasAccess()` (sets `SESSION = {r, id, name, who}` from localStorage `sp-access` = `{r, id, who}`; `who` = the name typed at login in `askName`, required; a plain hash string or a login without `who` is an older login and is asked for a name); otherwise `showLock` renders the login form. `SESSION.who` pre-fills "Prepared by" on new items, the request form and the approver's signing name. With all three lists empty everyone is an admin. `logout()` clears `sp-access` and reloads. Auto log-out: `startIdleWatch()` (called by `startApp`) tracks activity in localStorage `sp-active` (shared by tabs); after `IDLE_MS` (30 min) idle, `logout(true)` (skipped when the login was made with "This is my own device" ticked: `own: true` in `sp-access`/`SESSION`), with an `#idlewarn` "Stay logged in" bar shortly before; `hasAccess()` also ends a login whose `sp-active` is too old. Tests shorten `IDLE_MS` and restart the watch. `userBar()` is prepended to every page by `R()`.
- Routing: `R()` forces `T = "ap"` for approvers and leaves `"log"` for non-admins; `ApV` shows "Review a request" only to approvers and "Import an approval" only to others. The approver's login code is kept in memory (`APCODE`) for signing, never stored; after a reload they type it again and it must match `SESSION.id`.
- Admin only: Logs page (`goLog`), `clearAll`; `backupState()` drops `S.log`/`S.act` from full backups made by non-admins; "replace all" imports, clear all and Undo keep the current `S.log`/`S.act` (Undo restores them only when undoing their own clearing).
- PDFs carry `Ref <codeRef(hash)>` (first 6 hex characters of the hash, upper case) in the `Keywords` property (never as visible text) with the print time; `accessRef()` in `lock.js` (reference of the logged-in code, author, admin or approver), empty when no code is needed. `npm run code -- find REF` maps a reference to its name; `add` rejects codes whose reference clashes. The same ref is also drawn as invisible text (`renderingMode: "invisible"`), and as tracking dots (`refDots` in `pdf.js`, bits from `refBits`/`bitsRef` in `utils.js`: 6 hex digits + a mod-16 check digit, upper row = 0, lower row = 1; `npm run code -- dots "<bits>"` decodes).
- It is a deterrent only (public repo, client-side check). E2E tests set `sp-access` via `addInitScript` (first hash in `access.js`, or `{r: "admin", id}` from `admins.js` with `open(url, {role: "admin"})`); login tests serve replaced `access.js` / `admins.js` / `approvers.js` through `serve()`.

### Activity log (`activity.js`)
- `logAct(type, text)` unshifts `actEntry` (time, type `login`/`change`/`approval`/`delete`/`data`, text, `who`, `code`, `role` from `SESSION`) into `S.act` (max 5000). Before the data is loaded (`DATA_READY` false: login screen, idle end found by `hasAccess`), entries go to localStorage `sp-actq` via `queueAct` and `flushActQueue()` moves them in at start-up. `JUST_LOGGED` → "Logged in".
- Change history: `actTrack()` (called at the top of `R()`) snapshots the open item (`ACT_ITEM`, `copyData`) and company details (`CO_SNAP`); `flushItem()` logs `itemDiff(snap, now, S.co, kind)` (pure, in `utils.js`) when the item is left, before a PDF/deletion/request, on logout and when the tab is hidden. Other entries are logged where they happen (create/delete in `events.js`, `exportZip`/`applyImport`, approval steps, undo).
- `LogsV` renders the tabs; `ActV`, `LogV` (print log body), `CodesV` (`codeUsage()` from login entries and `S.log`); CSVs via `csvFile`.

### Print log and photo markup
- `logPdf` (`log.js`) is called by `mkPdf` after the download and unshifts an entry into `S.log` (max 2000; `who` = code name from `accessName()`, `person` = `SESSION.who`). `LogV` shows it with a filter (`LF`); `logCsv` downloads a UTF-8 BOM CSV.
- `markup.js` opens a full-screen editor outside `#app` (`#mk`, state in `MK`) for `data-a="mk"` buttons (`data-k` = `prod`/`pack`/`step`/`sub`). Its buttons use `data-mkt`/`data-mkc`/`data-mkx`, not `data-a`. Marks are drawn on a canvas at the photo's full resolution and saved by replacing the photo with a JPEG (after `remember`, rolled back if `writeNow()` fails); there is no separate original.

### Approvals (`approval.js`, crypto in `utils.js`)
- Approver codes → Ed25519 keys (`apKeys`: seed = `sha256("setup-procedures-approver:" + normCode(code))`, imported as PKCS#8 via Web Crypto). `js/approvers.js` holds `APPROVERS = [[name, publicKeyHex]]`, written by `scripts/approver-code.js` only.
- An approval covers `apContent(p, kind, deptName, imgHash)` (everything printed except "Approved by"/`ap`; photos by SHA-256 of their base64), hashed with `apFingerprint`. The signed `.json` is `{format: "setup-procedures-approval", payload: {decision, comment, approver, signer, at, fp, item, request}, pub, sig}` over `stableJson(payload)`; `apCheck` verifies it against `APPROVERS` and returns `name` (the `signer` the approver typed, signed with the decision; falls back to the list name) and `slot` (the list name, e.g. "Approver 1"), both shown in the app; the PDF prints only `name`, and hides `Approver ref <codeRef(pub)>` as invisible text and in Keywords (`apState` → `aref`).
- `p.ap` = `{st: "pending", to, req, fp}` or `{st: "approved"|"rejected", by, at, comment, fp, file, chg}`. The real state always comes from `apState` (re-verifies `file` and compares `fp` with the current content; cached in `AP_NOW`, refreshed after `R()` and 500 ms after typing by `apRefresh`). `chg` only feeds list badges. Drafts get `draftMark` in `mkPdf`; only `apState` = approved prints the approver's name.
- Request = `planItems` of the one item + `data.request` → `exportZip`; the approver's page (`T = "ap"`, `APR`) reads it with `readFile`/`fileContents` and makes a review PDF via `mkPdf({p, mm, line, coName, dept, logo, review: true})` without adding it to `S`. Emails open via `openMail` (mailto; tests replace `window.openMail`).

### Undo
`remember(msg)` must be called before a destructive change. It stores a deep copy of `S` (strings are shared, not copied) plus `T`/`V`/`MID` on a 20-entry stack and shows the toast. `undo()` restores state and re-renders. Small removals rely on Undo instead of `confirm()`; large ones (delete product/machine/line, replace all, clear all) confirm and also call `remember`.

## Conventions

- User-facing text is plain, short English; the in-app help panels (`xHelp`, `itemHelp`) and `README.md` describe behaviour and should be updated when features change.
- Keep the app working offline and from `file://`: no ES module imports and no network requests; libraries and fonts go in `vendor/` with their licence. `sw.js` (network first, cache fallback, and the cached copy after 4 s on a slow network) is registered only on http(s).
- ⋮ menus: `kebab(id, items, label, btn, cls)` in views.js; `MENU` = id of the open one (`"t"` page title via `titleMenu(title, items, extra)`, `"s:i"` step, `"u:i:j"` sub-step, `"user"` account). Items are built only while open. Title menu: line page rename/export/delete; product/machine page PDF options + Download PDF, approval actions (`apMenu(p)` by `AP_NOW` state), Duplicate, Export, Delete. Step ⋮: up, down, insert below, add sub-step, add note, delete; sub-step ⋮: up, down, add note, delete. A click outside or Escape closes it; choosing an option closes it (after the PDF or export finishes). E2E helpers: `openMenu(page, m)`, `menuClick`, `stepMenu`, `viewPhoto`, `logoutClick`, `settings`.
- Top bar (`userBar()` in lock.js): "Setup Procedures" (Home), ⚙ (`goSet` → `T = "set"`, `SetV`: company, backup, storage meter, logs and clear-all for admins), initials button (account menu with Log out; a `.vh` text keeps "Logged in: …" for screen readers). Home (`HomeV`): company, backup reminder, search, Products / Machines / Approvals cards. Logs and Export & import go back to Settings.
- Product/machine page: the title row has the approval badge (`#apbadge`, `apBadgeNow`; tap = `AP_OPEN`) and **?** (`HELPS.item`, help shown only while open). `#apbox` shows details only when `AP_OPEN`, a message (`APMSG`), a warning (changed after approval / after request) or the request form; it is hidden when empty. Sections are `<details class="sec" data-sec>` (`sec()`); closed ones are kept in `SECS` (sp-view `sec`). Step photos are buttons (`data-a="view"`) that open `#pv` (`VIEW`, `viewerHtml()`: Mark up, Remove, Close; Escape closes). Lists use "＋ New line/product/machine" (`add(ph, a, label, empty)`, `ADDING`; Enter adds, Cancel closes). Export & import has tabs (`XTAB` "ex"/"im"; loading files switches to "im").
- More: step photos reorder in the viewer (`phMv`). The title menu can switch to a line picker (`PICK` "dup" / "merge", `linePicker`): `dupP` with `data-l` duplicates into another line, `mergeL` moves a line's products into another (name clash → "Name (Old line)") and removes it (confirm + `remember`). Download PDF first runs `pdfChecks(p, kind)` (utils.js) and confirms if anything is listed. `mkPdf({..., batch: true})` returns `{file, blob}` (still logged; `logPdf` takes `mm`, `line`); `pdfZip(list, name, btn)` makes a .zip of PDFs (line ⋮ `pdfLine`, Machines page ⋮ `pdfMach`).
- Page states: `index.html` shows "Loading…" until `startApp` renders; if loading or the first render throws, `startApp` shows a "Could not open your saved data" screen. Empty lists use `<p class="empty">` (dashed box, also for "Nothing matches" with a Clear filter link). Search boxes are wrapped by `sbox(input, k)` (views.js) with a ✕ `data-a="sClear"` button (hidden by CSS while empty). Empty "Add" names use `needName()` (native validation bubble). Success messages use `toast(msg, false)` (PDF saved, export saved). Offline shows `.off` under the user bar (re-rendered on `online`/`offline`). A non-admin sent to `"log"` is moved home with a toast.
